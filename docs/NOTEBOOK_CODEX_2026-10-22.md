# Approved Campaign Codex

Deployed to production on 22 October 2026 with explicit user approval. See [release verification and rollback](NOTEBOOK_CODEX_RELEASE_2026-10-22.md). The implementation and local validation notes below describe the work before deployment.

The accepted subject-first layout now lives in the main campaign notebook, with People, Places, Objects & clues, Groups, Sessions and Bookmarks navigation. The library no longer has a Geography & folders filter. Folder organization and inherited sharing remain available under a separate DM-only Folder settings disclosure. Selecting a folder there does not filter the library. Description, Encounters and Connections retain the complete saved prose while source display uses session numbers.

Place entries open on an Overview with their description and accessible linked entries grouped into Connected places, Connected NPCs, Connected groups, Clues & discoveries and Related sessions. Other entries use the same groups in Connections. Incoming and outgoing links both contribute; hidden entries and entries beneath inaccessible folders are excluded before their category is returned. A connection does not assert containment or present-day residence. Plot notes can be written in the existing description; dedicated plot entries and location filters remain future options. No new campaign text or links are generated automatically.

Place editors can upload, preview, replace or remove a header image. JPG, PNG and WebP source files up to 10 MB are decoded locally, resized within 1600×900 and re-encoded as a JPEG of at most 250,000 data-URL characters. The protected entry holds the small raster; index/connection/history responses omit it, and no public asset URL is created. Existing entry and ancestor permissions apply to the image. Omitted image fields from older clients preserve the current image. Changing away from Places clears it. Text history does not store or restore images. The fixed header layers a 32% opacity image beneath a theme-colored fade; loading the image does not change its height, and entry transitions retain the existing motion preferences.

Image validation: actual browser file selection resized a 4000×2400 PNG (5.8 MB) to 1500×900 JPEG (~40 KB). Invalid SVG input retained the prior image; save/removal, private detail rejection, authorized phone player rendering, and stable frame/header/document scroll passed. Route/payload tests cover format/size rejection, place-only images, old-client preservation, list omission, ancestor permissions, preview write rejection, removal, and text-only history behavior. The developer server was resumed with the user's local Amdurnu entry and history intact; a separate disposable server handled image fixtures.

The API supports cross-collection browsing, category filters/counts, chronological sessions, source links, accent-insensitive full-text search, and pagination after filtering. All navigation metadata is derived after entry and ancestor-folder access checks; inaccessible titles, categories and session links are not returned. Existing entries derive their initial category from their saved collection/title. A nullable category field allows explicit category choices on later saves without a migration. DM edits can move entries between collections after destination-folder validation; player permissions are retained.

The saved Markdown, campaign entries, their sharing and geographic placement are not rewritten during this change. Reading tabs and source cleanup are presentation only. The existing whole-entry permission model remains. Version restoration still restores title/body only.

Animations reuse the site's balanced motion: entry changes and editor opening fade/translate the reader, tabs animate their content, and category results animate after their request completes. Background refresh leaves reading content still. Buttons and disclosures retain global feedback. The appearance panel and OS reduced-motion settings disable these animations. The notebook keeps independent list/reader scroll, a bounded loading frame, Back restoration and stable phone library/reader switching.

The local notebook server now uses the same component as production with disposable copies and a local-only banner/reset. Run `npm.cmd run preview:notebook`, then open http://localhost:5182/rooms/000000000000000000000ca1?section=notebook. The prior duplicate preview component was removed.

Validation: focused shared metadata, actual API-route permission/category/pagination/editing tests and existing scroll/loading regressions passed (39 tests). Frontend and server typechecks passed. Browser checks confirmed entry/tab/list animations, quiet refresh, both reduced-motion controls, numeric session order and stable desktop scroll. Additional editor, player-view and phone checks use the local approved-copy server. No deployment or live campaign write is part of this implementation.
